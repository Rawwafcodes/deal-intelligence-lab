# Experience: flexible mandates and live team work

## Navigation
Workspace: Overview / Deals / Mandates / Documents / Findings / Activity.
Deal: Overview / Mandates / Workstreams / Documents / Findings / Requests & Tasks /
Deliverables / Activity. Secondary views can be tabs, not a mandatory sidebar explosion.
Global views always filter by access. A deal-independent mandate is first-class.
Do not force duplicate data copies when viewing the same record at different levels.

## Mandate composer
Ask 'What do you need accomplished?' first.
Then show context, approved sources, optional template, output and reviewer.
Advanced budget/tool/model controls progressively disclose.
AI proposes a readable plan. User can amend it conversationally or edit approved fields.
Show data leaving the machine and estimated usage before execution.
Unknown estimates say unknown. Templates never imply unavailable capabilities work.
Simple mandates can have one stage; avoid approval bureaucracy for every internal thought.

## Mandate detail
One page renders objective, current stage, plan, questions, sources/coverage,
findings, deliverables, human approvals, activity and usage.
Waiting states say who must do what. Failure preserves partial work and explains
what is safe to retry. Show draft versus published and AI versus human explicitly.

## Workspace Overview
My attention: approvals, questions, submitted work, blocked assignments.
Active engagements: owner, current stage, material unresolved matters and next action.
Mandates: running, waiting, under review, recently completed and failed.
Material changes: new submissions/evidence, reopened issues, approvals.
Quick actions: new mandate, new deal, upload, assigned reviews.
Counts derive from real records with visible filters. No invented percent-health metrics.

## Deal Overview
Brief header; latest human-approved position with version/date; urgent matters;
mandates; workstream responsibilities; material issues; requests; changes;
latest deliverables and approvals. If no approved position exists, say so.
An AI draft summary cannot impersonate the lead's approved conclusion.

## Analyst journey
Assignment → source access → mandate or human work → submission version →
AI/human review → revision request → revised submission → approval.
Work stays in Excel/Word initially; upload versions for shared review.
Supported analysis formats must be distinct from accepted upload formats.

## Principal journey
Workspace → deal → workstream → assignment → submission → claim/evidence → review.
MD can inspect submitted analyst work, mandates, decisions and revisions within scope.
Never equate more revisions or more citations with poorer/better employee performance.
External executive view exposes approved shared materials only by default.

## Resolution
Response received ≠ evidence received ≠ evidence reviewed ≠ correction made ≠
closure approved. Record rationale and linked evidence on closure. Residual-risk
acceptance is different from factual resolution. New evidence may require reassessment.

## Live behavior
Multi-browser sessions share authoritative state. Begin with bounded polling and
revision checks; server events are optional later. Display refresh/error state.
Concurrent writes produce an explicit conflict and allow reload/reapply.
No co-editing engine or keystroke surveillance required.

## UI quality gate
Select the permanent frontend approach before new permanent screens. Inspect existing
React assets; reuse if suitable. Shared components for tables, evidence, status,
approval and empty/loading/error states. Actual keyboard controls, focus management,
readable Arabic/English mixed text, reduced motion and narrow-width testing.
Use fixture-driven prototypes to validate workflow, not to claim AI quality.
