# M16 — Continuous workspace integrity

Status: proposed and evidence-gated.

M16 deepens the tested M14/M15 capability. It must not begin merely because the architecture is attractive.

## Entry gates

All must hold:

- M13 collaboration is proven with multiple identities.
- M14.2 has at least one independently scored real authorized case.
- M15 version dependencies and reassessment work.
- Review outputs show recurring reusable assertions.
- Measured failure modes justify more structure than a strong LLM plus native document access.

## 16.1 Taxonomy and golden set

Build a versioned set of known cases across:

- Numerical conflict.
- Temporal/period mismatch.
- Unit/currency mismatch.
- Derivation divergence.
- Entity conflation.
- Modality escalation.
- Unsupported assertion.
- Staleness.
- Logical contradiction.
- Comparator/specificity mismatch.

Use authorized real examples or synthetic reconstructions of patterns. Do not move confidential client content into a reusable corpus without authority.

## 16.2 Evidence assertion ledger

Promote proven assertion snapshots into reusable, versioned evidence records.

Requirements:

- Stable identity separate from content hashes.
- Source-version and locator provenance.
- Original wording and language.
- Optional normalized fields.
- Modality and verification status.
- Supersession history.
- Extraction/prompt/model version.
- Human confirmation and dispute state.
- Relationships to submissions and findings.

Never require all prose or judgments to become rigid subject-predicate-object triples.

## 16.3 Deterministic reconciler

Implement rules one at a time, each justified by the golden set.

For each rule define:

- Preconditions.
- Normalization assumptions.
- Tolerances.
- Blocking/challenge/review-queue tier.
- Evidence presentation.
- Override and dismissal reason.
- Regression fixtures.

Start with the least ambiguous checks. Do not claim zero false positives without measured evidence.

## 16.4 Semantic review

Benchmark at least:

- Current strong-model review.
- Retrieval-gated strong-model review.
- Any proposed NLI-plus-model pipeline.

Add infrastructure only where it measurably improves accuracy, cost or latency on the golden set.

## 16.5 Incremental evaluation

Reevaluate only changed assertions and their recorded dependencies. Full reassessment remains an explicit mandate. Cache only when source/version/prompt/model identity makes reuse valid and auditable.

## 16.6 Inline assistance decision

First attach challenges to immutable submission spans or anchored sections. Consider a native CRDT editor only if user evidence shows submission-time review is too late and the benefit justifies building a document editor.

## M16 completion outcome

The system detects and manages cross-source and cross-author integrity issues as part of normal work, while preserving uncertainty, human authority, evidence lineage and historical versions.
