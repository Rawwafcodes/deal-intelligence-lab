Status: in_progress

2026-09-27 re-entry audit report (chat-only; not itself a repository

Dependencies: all of M11-M16 (see `STATUS.md` and the M1-M16

integration/product-architecture program over already-implemented
capabilities, not new backend work.

## Objective
Turn the substantial backend already built through Milestone 16 into one
coherent, React-native product in which users can reach and operate every
relevant completed capability through the intended six-destination
interface (Overview, Deals, Mandates, Documents, Findings, Activity).
This is an integration phase. It does not authorize a new backend, a
rewrite of proven domain logic, or cloud deployment.

## Ground rules (binding on every sub-task below)
- React is the permanent frontend. Do not restore a user-facing "legacy
  page" exit as the solution to a reachability gap.
- Reuse existing backend routes, schemas and domain logic wherever they
  already satisfy the workflow. Do not create parallel models or
  duplicate implementations because existing code is inconvenient.
- Do not rewrite the mandate runtime, worker, capability registry, or the
  Python server framework.
- No paid Anthropic calls, no real confidential documents, no cloud
  deployment, no provider migration, no PostgreSQL replacement anywhere
  in this program.
- One bounded commit per independently reviewable task. Do not combine
  the whole program into one commit.
- Do not push to GitHub without the founder's explicit approval.

## Acceptance criteria for the program as a whole
- Every backend-complete workflow named in Phase A has a reachable,
  React-native path inside the current product. No normal workflow
  requires a user to discover or hand-type an old static page's URL.
- Static pages may remain internally for capabilities not yet migrated,
  but are not presented as the preferred experience (only `validation.html`
  is expected to remain a deliberate, disclosed exception per D13/the
  2026-09-27 audit - Validation Lab is explicitly out of this program's
  scope, per the product/mandates docs' own Review-vs-Validation-Lab
  boundary).
- Full backend test suite, mypy, frontend `tsc -b`, `oxlint`, `npm run
  build`, and the `tests/frontend/*.test.mjs` suite all pass before any
  sub-task is marked complete.
- A live browser check (this environment uses Playwright against the
  locally running server, since no human browser is available in this
  cloud container) confirms the new surface renders real backend data,
  with no new console errors, for every UI change.
- `STATUS.md` is updated with each completed sub-task's own dated entry,
  following the existing convention exactly (baseline, what changed,
  test evidence, files changed, decisions, blockers, next task).

## Explicit non-goals for this program

  not addressed by this program.

  claim activation — Phase D requires an explicit smallest-useful-
  integration analysis first, and a founder decision if that integration
  turns out to be product-significant (see `17.8` when written).
- Any cloud/production-readiness work.
- Any claim that this program constitutes commercial validation of M16's
  analytical capabilities.
