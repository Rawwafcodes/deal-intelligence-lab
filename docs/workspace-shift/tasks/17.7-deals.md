# Task 17.7 — Distinct Deals destination
Status: complete
Authorization: founder directive, 2026-09-27 (Phase B2 of
`17.0-product-integration-program.md`).
Dependencies: 17.6 (Overview now real; this task trims its Active
Engagements section and moves deal creation here, closing the "avoid a
dead link" deferral 17.6's own task file recorded).

## User outcome
A new `/deals` destination lists every accessible deal with real role
information, real task/mandate exposure counts, the most recent
material change on that deal (if any), search, and the deal-creation
action - separate from Overview, matching the canonical six-destination
IA. Selecting a deal still goes to its own Deal Overview, unchanged.

## Required reading
docs/product/02's Deals spec ("all accessible deals; useful status and
role information; current phase or workflow state where supported;
material unresolved exposure; latest relevant activity; creation/
opening actions; filters and search"); the existing `/api/overview`
payload (`engagements`, `material_changes` - both already real, from
17.6); `identity.py`'s deal-membership routes (already used by
`DecisionPackage.tsx`/`Triggers.tsx` for "my role").

## Baseline
HEAD at `ab4b784` (Task 17.6). Full suite green. Confirmed by direct
inspection: `store.Project` has no "phase"/"stage"/"workflow state"
field at all - there is no real backend concept of a deal's own phase
to show. `Home.tsx` (Overview) still held the full engagement list and
the create-deal dialog before this task, per 17.6's own explicit
deferral.

## Scope
1. New `frontend/src/routes/Deals.tsx` at `/deals` (a peer route to
   `/`, `/projects/:id`, not nested under `DealShell`). Fetches the
   existing `/api/overview` payload (reused, not duplicated - one call
   already gives `engagements` and `material_changes`) plus, in
   parallel, `listDealMemberships` for every accessible project (the
   same pattern `DecisionPackage.tsx`/`Triggers.tsx` already use for "my
   role"). Renders each deal with: name/description/created date; my
   role (real, from the membership row); real task/mandate exposure
   counts (the honest stand-in for "current phase/workflow state,"
   since no real phase field exists - disclosed, not papered over with
   an invented label); the most recent `material_changes` entry for
   that project, if any (derived by grouping the already-fetched feed,
   zero new fetches); a link to open the deal. A search input filters
   client-side by name/description. The existing create-deal dialog
   moves here from `Home.tsx` (not duplicated in both places).
2. `App.tsx`: register `/deals`. `AppSidebar.tsx`: add a real top-level
   "Deals" link (see 17.8 for the fuller nav pass, once Mandates also
   has a home - this task adds the Deals link specifically since it's
   the destination this task builds).
3. `Home.tsx`: trim Active Engagements to the 5 most recently created
   accessible deals with a "See all deals" link to `/deals`; "Create a
   deal" (both the header button and the Quick Action) now link to
   `/deals` instead of opening a local dialog - one dialog, not two
   copies of the same form.
