## Scope

1. **Export formula-injection fix** — `workspace_exports.py`'s
   `_write_table()` (used by both `build_findings_workbook` and
   `build_requests_workbook`) writes free-text fields directly into
   `openpyxl` cells. Add a single small helper,
   `_safe_cell_text(value: str) -> str`, that prefixes the value with `'`
   when it starts with `=`, `+`, `-`, `@`, or a leading tab/CR, and route
   every string value through it before it reaches `ws.cell(..., value=...)`
   in `_write_table` and `_write_header_sheet`. Applies to every affected
   column (`title`, `assigned_owner`, `management_response`,
   `reviewer_notes`, human-finding `evidence_notes`, request `question`/
   `assigned_recipient`, everything currently passed through unmodified).
2. **`adjusted_severity` regression (frontend)** — in `static/workspace.js`,
   extract the existing inline fix (`{ ...values, adjusted_severity:
   values.adjusted_severity || null }`, currently only inline in the save
   button's click handler) into a small named, pure function,
   `buildFindingUpdatePayload(values)`, and call it from that handler.
3. **Workspace-summary-refresh regression (frontend)** — the two call sites
   that mutate a request and must also refresh `report.summary`
   (`await Promise.all([loadRequests(), loadWorkspace()])`, currently two
   separate inline call sites) stay as-is functionally; add a short comment
   at each site pointing at the regression test in scope item below, so a
   future edit that drops the `loadWorkspace()` call is more likely to be
   caught by a reviewer even before the test runs.
4. **Accessibility fix** — `static/workspace.js` currently sets
   `row.setAttribute("role", "button")` on a `<tr>`, which the accessibility
   tree is expected to ignore (a `button` role is invalid on a table-row
   child per ARIA's required-context-role rules) even though `tabIndex = 0`
   and the `keydown` handler both still work. Replace the row's expand
   affordance with a real `<button>` element for the expand/collapse control
   (first cell), keeping the row's own click-to-expand behavior for mouse
   users, so the control is both keyboard-operable (already true) and
   correctly announced as an interactive control (not true today).
5. **Minimal test tooling, chosen not assumed** — no new dependency. Both
   regressions above are covered by a single new file,
   `tests/frontend/workspace.logic.test.mjs`, using Node's built-in
   `node:test` + `node:assert` (no `jsdom`, no bundler): re-implement
   `buildFindingUpdatePayload` as a tiny standalone export at the top of
   `static/workspace.js` (a pure function with no DOM dependency, callable
   in plain Node) and import it directly. This is deliberately narrow — it
   proves the one fixed bug stays fixed, not a general DOM-testing
   framework. A broader frontend-testing decision remains open (noted in
   the adoption report, not decided here).
