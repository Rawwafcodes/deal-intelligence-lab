Status: complete
Authorization: founder said "next" immediately after Task 16.5's
completion summary, which named 16.6 as the last remaining M16 roadmap

Dependencies: `integrity_reviews.py`/`integrity_review.py` (Task 14.2) -

## User outcome
A reviewer looking at an Integrity Review candidate can now see exactly
which passages of the submission, source documents, and peer submissions
the model actually cited, and click through to open the real underlying
PDF at the exact page - anchored to the immutable version that was
actually reviewed, not "whatever the document happens to be today."
Previously this data existed in the API response but was rendered
nowhere at all.

## Scope
**Part 1 (attach challenges to spans) - implemented in full:**
1. `frontend/src/lib/api.ts`: new `PdfCitation`/`ExcelCitation`
   interfaces matching the backend's `to_dict()` shapes exactly; added
   `pdf_citations`/`excel_citations` to `IntegrityCandidate`; added the
   previously-missing `source_version_ids`/`peer_version_ids` to
   `IntegrityReview` (these were already returned by the API but never
   typed, since nothing needed them before). New pure function
   `buildPdfCitationHref(projectId, review, citation)` resolves a
   citation's `document_id` against `review.target_work_product_id`
   (submission), `review.peer_work_product_ids` (peer submission, via
   index-matched `peer_version_ids`), or `review.source_document_ids`
   (source document, via index-matched `source_version_ids`) and returns
   a version-pinned download URL with `?inline=1#page=N` - always the
   *exact version actually reviewed*, never "whatever is current now."
2. `frontend/src/routes/MandateDetail.tsx`: each candidate now renders a
   "Cited passages" section - one chip per `pdf_citations` entry (page
   label + the document's own title, `cited_text` as a hover tooltip,
   linked via `buildPdfCitationHref` when a document id is present) and
   one chip per `excel_citations` entry (sheet/cell reference, no
   page-jump link - see Exclusions).
3. **`server.py` fix** (found necessary, not planned in advance): the
   work-product version download route never read or forwarded the
   `inline` query parameter at all (its two document-route siblings
   already did). Fixed to match - one `parse_qs` call and one parameter
   forward, identical to the existing pattern.

**Part 2 (CRDT editor) - correctly not built:** the spec's own
conditional language ("only if user evidence shows submission-time
review is too late") is not met - no such evidence exists anywhere in
this codebase or this effort's own history. Per the spec's own structure,
not building it is the compliant outcome here, not a scope cut - see
Exclusions for the full reasoning.

## Exclusions
- **No CRDT/live collaborative editor**, per the spec's own explicit
  condition not being met. This is not deferred as "future work needing
  its own task" in the same sense as, say, Task 16.4's other two legs -
  the spec frames it as something to build only *if* evidence emerges
  that submission-time review is too late, and no such evidence exists.
  Revisiting this is appropriate only if that evidence appears later.
- **No visual PDF highlight/overlay.** Clicking a citation opens the
  real PDF at the correct page (via `#page=N`); it does not additionally
  highlight or scroll directly to the cited text within that page. This
  would require either a custom PDF.js-based viewer with text-layer
  search (real, nontrivial browser engineering) or relying on a
  browser's native PDF viewer supporting text search on load (not a
  standard capability across browsers). Page-level anchoring was judged
  the right "first" step; more precise anchoring is a natural
  incremental follow-on once page-level anchoring itself proves useful.
- **No "jump to cell" for Excel citations.** Unlike a PDF's `#page=N`
  fragment, there is no standard browser convention for deep-linking into
  a specific worksheet/cell of a downloaded `.xlsx` file. Excel citations
  are rendered as informative text (sheet + cell reference, kind, and a
  warning glyph when `exists === false`) with no click-through link -
  disclosed as an honest limitation, not silently downgraded to a plain
  download link that would misleadingly imply page-jump behavior.
- **No automated frontend test.** No TypeScript test runner exists in
  this repository for the React app; introducing one (vitest, etc.)
  solely to cover one new pure function was judged disproportionate -
  verified instead via `tsc -b` (clean), `oxlint` (no new warnings), and
  a real, zero-cost, full-integration live browser check (see Completion
  evidence) that exercises the actual rendered DOM, actual hrefs, and
  actual backend response headers together.
- **No route/backend change beyond the one work-product-download fix.**
  Every other piece of data this task needed already existed in the API
  response; nothing about `integrity_reviews.py`/`integrity_review.py`
  changed.

## Reuse
Reuses Task 14.2's own `pdf_citations`/`excel_citations` data (already
computed, already correct, already returned by the API - zero new
extraction or citation logic) and the two already-existing,
already-correct document download routes' `inline` handling as the
template for fixing the third (work-product) route to match. No new
schema, no new backend module.

## Security and intelligence boundary
No new identity, input, or tool surface. `buildPdfCitationHref` only
ever constructs URLs to this app's own existing, already-authorized
download routes (which already enforce `_authorized_project` project
membership before serving any file) - it never accepts or renders a
caller-supplied URL, and a citation with an unrecognized `document_id`
falls back to a plain current-version document download rather than
producing a broken or unsafe link.
