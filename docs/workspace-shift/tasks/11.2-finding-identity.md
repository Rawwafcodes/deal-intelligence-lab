# Task 11.2 — Stable finding UUIDs, immutable snapshots, audited legacy migration
Status: complete
Authorization: `docs/08-roadmap.md` M11.2; founder requested this task directly in
session, after reviewing 11.1's completion; scope confirmed with the founder before
implementation (migration approach, and whether to apply it to the real database in
this session — founder chose: build, validate on a clone, then apply for real).
Dependencies: Task 11.1 (closeout)

## User outcome
Every AI-origin finding now has a permanent, randomly-generated id
(`ai-<uuid>`) and an immutable content snapshot captured once, at workspace
creation, instead of an id tied to its position in the parser's output and
content re-derived from the analysis record on every read. The real
Universal Logic workspace's 33 AI findings (plus their review state,
duplicate marking, and information request) were migrated to this scheme
in this session, with a full audit trail and a kept backup.

## Scope
1. **Schema** (`workspaces.py: init_workspaces_db`): additive
   `ai_extraction_version`, `ai_snapshot_json`, `ai_content_hash` columns
   on `workspace_findings`, added via an idempotent `PRAGMA table_info`-
   guarded `ALTER TABLE` (`_ensure_finding_snapshot_columns`) so it's safe
   to run against an already-migrated database. `ai_finding_index` kept as
   provenance only.
2. **New-workspace path**: `evaluations.EXTRACTION_VERSION = "v1"` added.
   `workspaces._insert_ai_finding_row` now takes the already-extracted
   finding dict, mints `id = f"ai-{uuid.uuid4().hex}"`, and persists the
   snapshot/version/hash at insert time. `_merged_finding`/`list_findings`
   no longer call `evaluations.extract_findings` on the read path at all —
   `get_or_create_workspace` is the only caller, once, at creation.
   `create_human_finding` untouched (already stable UUIDs, already stores
   its own content).
3. **Migration script**: new `migrate_finding_ids.py` (repo root).
   `--dry-run` (default; copies the target database — the real one unless
   `--db` is given — to a throwaway temp file and migrates the copy only),
   `--verify-only` (read-only integrity check), `--apply` (backs up the
   real database to a timestamped sibling file, then migrates it in
   place). Refuses to write if any legacy row is unresolved (its recorded
   index doesn't exist in a fresh re-extraction), unless
   `--allow-unresolved` is passed, in which case that specific row is left
   untouched and reported, everything else still migrates. Every rename
   remaps `duplicate_of`, `workspace_requests.related_finding_ids_json`,
   and `workspace_audit_log.entity_id`, and logs its own
   `finding_id_migrated` audit event.
4. **Tests**: `tests/test_workspaces.py` and
   `tests/test_workspace_endpoints.py` updated (~30 call sites) to look up
   a finding's id by its known title instead of assuming a literal
   `"ai-0"`/`"ai-1"` string — expected churn, the whole point of the task
   removes that assumption. New `tests/test_finding_id_migration.py`
   (9 tests): scan/apply/verify round-trip, idempotent re-run,
   duplicate_of/related_finding_ids/audit-log remap, the unresolved case
   (refuses without `--allow-unresolved`, migrates the rest with it), and
   the CLI's dry-run (never touches the real file) and verify-only modes.
