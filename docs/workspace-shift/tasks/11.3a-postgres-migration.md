# Task 11.3a — Move the local database from SQLite to PostgreSQL
Status: complete
Authorization: roadmap M11.3a ("decide and record SQLite/WAL versus local
Postgres before collaborative schema"). Founder rejected the evidence-based
SQLite+retry-wrapper recommendation (P06) directly, in session, and chose
Postgres instead — a preference decision, not an evidence-driven one (see
docs/10-decisions.md D11). Full scope (install method, and "everything now"
vs. proof-of-concept vs. decision-only) confirmed with the founder via
AskUserQuestion before implementation; a written plan was then approved
(ExitPlanMode) before any code was touched.
Dependencies: Task 11.2 (finding-identity migration — its output data is
what actually got carried into Postgres)

## User outcome
The app's entire local database is now PostgreSQL instead of SQLite,
installed with no system-level changes (conda, not Homebrew — Homebrew
itself wasn't installed and installing it needs an interactive sudo prompt
this session can't satisfy). The real local database — every project,
including Universal Logic's 34 findings, its duplicate marking, its one
information request, its memo, and its 56-entry audit log — was migrated
for real, verified row-count-exact and content-byte-exact, and the running
app now reads and writes Postgres exclusively.

## Required reading
`docs/10-decisions.md` (D11, P06, O03); `store.py`; the module-by-module
survey performed at the start of this task (see STATUS.md's dated entry for
its findings — every module and test file that touches the database).

HEAD at `fd59122`, unchanged (no commits made). 335 tests passing, mypy

## Scope
1. **Installed Postgres via conda** (`conda install -c conda-forge
   postgresql`) into the existing Anaconda environment — no Homebrew, no
   sudo. Initialized a project-local data directory (`pgdata/`, UTF8
   encoding, `en_US.UTF-8` locale — real deal content isn't ASCII-only)
   and started it on a Unix socket only (`pgsocket/`, port 5544, no TCP
   listener, `trust` auth, no password). `psycopg2-binary` added to
   `requirements.txt` and installed into `venv/`.
2. **Rewrote `store.py`** (the sole SQLite choke point — confirmed by
   survey that nothing else in the codebase calls `sqlite3.connect`
   directly): `get_connection()` now returns a thin `_ConnectionWrapper`
   around a psycopg2 connection that still supports the same
   `conn.execute(sql, params).fetchone()/.fetchall()` shorthand every
   other module already used, with `RealDictCursor` so `row["column"]`
   access is unchanged everywhere. New `SCHEMA` module global (replacing
   `DB_PATH`) plus `ensure_schema()`/`drop_schema()`, used by every test
   file for isolation (one throwaway Postgres schema per test/class,
   dropped after — the same role a fresh temp SQLite file used to play).
3. **Ported the other 10 schema-owning modules** — `documents.py`,
   `inspections.py`, `xlsx_inspections.py`, `cross_analyses.py`,
   `cross_format_analyses.py`, `validation_cases.py`, `answer_keys.py`,
   `validation_runs.py`, `evaluations.py` (only its DB-storage half —
   `extract_findings`/`EXTRACTION_VERSION` are untouched, unrelated to
   SQL), `workspaces.py` — each a mechanical `?`→`%s` placeholder swap,
   zero business-logic changes. `workspaces.py`'s
   `_ensure_finding_snapshot_columns` collapsed from a `PRAGMA
   table_info`-based existence check to plain `ALTER TABLE ... ADD COLUMN
   IF NOT EXISTS` (native in Postgres, not in SQLite). Column types
   (`INTEGER` 0/1 booleans, `TEXT` JSON columns) deliberately left
   unchanged — a 1:1 backend swap, not a schema redesign.
4. **Ported all ~22 affected test files'** DB fixture setup from
   "monkeypatch `store.DB_PATH` to a fresh temp file" to "monkeypatch
   `store.SCHEMA` to a fresh Postgres schema name" — same shape, same
   scope (class- vs. per-test, wherever the file already used it), no
   change to actual test assertions or fixtures beyond the DB-isolation
   boilerplate. This included `tests/test_xlsx_inspection.py` — one of
   the four files this whole workspace-shift effort has repeatedly kept
   hands-off (a concurrent session's uncommitted work on the *singular*
   `xlsx_inspection.py` module) — disclosed explicitly below, not hidden.
5. **Retired `migrate_finding_ids.py` and its test** (`tests/
   test_finding_id_migration.py`). Its one job — converting legacy
   `ai-<index>` finding ids to stable `ai-<uuid>` ids with snapshots — is
   already complete and verified against the real data (Task 11.2). It was
   tightly coupled to SQLite file semantics (`store.DB_PATH`, file-copy
   dry-runs) that don't carry forward to Postgres, and porting a tool
   whose real-world job is finished would be maintaining dead weight.
6. **New `migrate_sqlite_to_postgres.py`** — the one-time real-data
   transport. Generic by construction: reads each table's column list
   straight from SQLite's own `PRAGMA table_info` rather than a
   hand-maintained list, so it can't silently drift from the real schema.
   Read-only against `data/deal_lab.db`. Calls all 11 `init_*_db()`
   functions first (identical to `server.py`'s own startup sequence) so
   every destination table exists before any row is copied.
7. **Executed the real migration**: stopped the running (SQLite-backed)
   server, ran the transport script against the real `data/deal_lab.db`
   into the fresh Postgres `public` schema, verified, restarted the server
   (now Postgres-backed).
8. **Docs**: `docs/10-decisions.md` D11 added (Established direction), P06
   marked rejected (kept, not deleted, with the reason), O03 marked
   resolved. New `POSTGRES.md` (start/stop/psql commands, env var
   overrides, test-isolation model). `README.md`'s "How to run it" and
   "Your data" sections updated to mention starting Postgres first and to
   correct where data now lives. `.gitignore` updated for `pgdata/`,
   `pgsocket/`, `pgdata.log`.

## Exclusions
No connection pooling, no native `BOOLEAN`/`JSONB` column redesign, no ORM.
No `Organization`/`Mandate`/collaborative-schema work (still 11.3b+,
unblocked but not started). No deployment, no push, no paid AI calls, no
`git commit`.

## Reuse
Every module's own existing functions, DDL shape, and validation logic are
reused byte-for-byte beyond the placeholder/connection-layer change — this
was a backend swap, not a rewrite. `server.py`'s own startup call sequence
was reused directly as the reference order for
`migrate_sqlite_to_postgres.py`'s `init_all_postgres_tables()`.

## Security and intelligence boundary
No AI/model code touched. Postgres listens on a Unix socket only (no TCP,
no network exposure, no password to leak). No new external transmission.
