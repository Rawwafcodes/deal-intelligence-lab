## The constraint that shapes everything

Track B's methodology (`13-post-m17-roadmap.md`) requires answer keys
created and locked **before** the product runs, answer-key content kept
**out of model requests**, and **no LLM grading** of qualitative
correctness. `answer_keys.py` enforces the same thing in code: key content
"must never reach Anthropic in any form".

An AI agent doing this work (Claude, via Anthropic) is therefore limited
to:

- **Can do**: set up cases and documents, run the product blind, measure
  the mechanical metrics (runtime, tokens/cost, citation locator validity,
  quoted-value accuracy, calculation reproduction, repeatability across
  runs, failure modes), and prepare the scoring forms.
- **Cannot do**: write or read an answer key, or judge whether a finding
  is correct against it. That must be a human - the founder or,
  preferably, an independent evaluator. Doing it anyway would make the
  whole Track B result worthless as independent evidence.

## Thresholds

Track B requires provisional thresholds proposed and recorded as a
decision, founder-approved, **before scoring**. Proposal to approve or
change (deliberately modest, since there is no prior evidence):

| Metric | Provisional threshold |
|---|---|
| Critical expected-issue recall | ≥ 80% |
| High-severity expected-issue recall | ≥ 60% |
| Reviewed-finding precision (correct ÷ findings rated) | ≥ 70% |
| Citation locator validity | ≥ 95% |
| Quoted-value accuracy | ≥ 95% |
| Unsupported-claim rate | ≤ 10% |
| Repeatability (critical issues found in every run) | ≥ 2 of 3 runs |

These are for recording a pass/fail against a stated bar, not claims
about what is good enough to sell.
