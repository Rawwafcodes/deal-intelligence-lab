# Task 17.11 — Unify Findings display across workspace origins (Phase D, part 2)
Status: complete
Authorization: this program's own Phase D scope ("create one
professional findings register across supported origins... where
available: cross-format reconciliation findings; Integrity Review
findings"); the specific gap was reconfirmed live during Task 17.10's
own verification, not newly discovered here.
Dependencies: 17.10 (Assertions view/assertion ledger wiring, commit
`5ed7df4`).

## User outcome
Opening Findings for a deal whose most-recent (or selected) workspace
is Integrity-Review-backed no longer hits a 400 error or a "this screen
doesn't yet render that kind of workspace's findings" placeholder card.
Both cross-format-analysis-backed and Integrity-Review-backed
workspaces now render through the exact same findings register, with
honest (not fabricated) summary fields when no `CrossFormatAnalysis`
exists.

## Required reading
`workspaces.py`'s `list_findings`/`compute_summary` docstrings (already
stated analysis is "genuinely optional - an integrity-review-backed
workspace has no CrossFormatAnalysis at all" before this task started);
`server.py`'s `_handle_get_workspace` and `_get_workspace_analysis`;
`Findings.tsx`'s placeholder branch; the 2026-09-18 frontend-unification
STATUS.md entry that first disclosed this boundary.

## Baseline
HEAD at `5ed7df4` (closes Task 17.10/D1). Full suite green (869 tests)
at start. Confirmed by direct inspection: `_handle_get_workspace`
unconditionally called `self._get_workspace_analysis(workspace)`, which
returns a 400 whenever `workspace.cross_format_analysis_id is None` -
even though `workspaces.list_findings()` had already been written to
accept `analysis: CrossFormatAnalysis | None` and works correctly with
`None`. The 400 was a leftover integration gap, not a real backend
limitation.

## Scope
**Backend** (`server.py`): rewrote `_handle_get_workspace` to fetch a
`CrossFormatAnalysis` only when `workspace.cross_format_analysis_id is
not None`; otherwise `analysis = None`. Still 404s if
`cross_format_analysis_id` is set but the record is genuinely missing
(data-integrity case, unchanged). Response now returns `"analysis":
analysis.to_dict() if analysis else None` instead of always requiring a
non-null analysis. `_get_workspace_analysis` itself is untouched, since
`_handle_get_memo`/`_handle_export_decision_package` still genuinely
require a real `CrossFormatAnalysis` and correctly keep 400ing when one
doesn't exist.

**Backend** (`workspaces.py`): widened `compute_summary`'s signature to
`analysis: cross_format_analyses.CrossFormatAnalysis | None` and made
every analysis-derived field conditional: `document_count`,
`pdf_document_count`, `excel_document_count`, `model`, `input_tokens`,
`output_tokens`, `analysis_created_at` all fall back to `0`/`None` when
`analysis` is `None`, rather than raising `AttributeError` (a real crash
this task found while writing its own test - see below).

**Frontend** (`Findings.tsx`): removed the `!selected.cross_format_
analysis_id` placeholder branch entirely; the bundle now renders
findings identically regardless of origin. (`api.ts`): widened
`WorkspaceBundle.analysis` from `Record<string, unknown>` to
`Record<string, unknown> | null` to match the real backend contract.

## Exclusions
- No change to `_get_workspace_analysis`, the memo/export handlers, or
  any other caller that genuinely requires a `CrossFormatAnalysis` -
  this task only touches the one workspace-bundle read path that
  `workspaces.py` had already been written to support without one.
- No UI differentiation between the two origins beyond what the data
  itself implies (an Integrity-Review-backed bundle simply has fewer
  populated summary fields) - a single register, per this program's own
  Phase D framing, not two skinned views.
- No retroactive backfill or migration - purely a read-path fix.

## Reuse
`workspaces.list_findings`/`compute_summary` (already analysis-optional
by design before this task); no new backend capability, only a real
integration bug fix connecting an existing, already-correct capability
to its HTTP handler.

## Security and intelligence boundary
No AI, no new routes, no new authorization surface. Same
`_get_owned_workspace` project-ownership check as before, unchanged.
