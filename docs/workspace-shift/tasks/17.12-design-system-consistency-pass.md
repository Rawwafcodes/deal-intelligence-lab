## Scope
Real, live audit (not a hypothetical read-through): took full-page
Playwright screenshots of all six top-level destinations at 1440x900
against the actually-running app, then grepped the entire
`frontend/src` tree for known anti-patterns (hardcoded non-token
colors, unstyled native `<button>`/interactive elements). Fixed what
was actually found:

- **Real accessibility bug, 3 sites**: `text-accent` used as a link
  text color in `Home.tsx` (the "See all deals →" header link and each
  engagement card's "Mandates →" link) and as a `hover:text-accent`
  state in `Documents.tsx` (document filename links). `--accent`
  (`#1b1b20`) is a near-black *background* token meant for hover-fill
  surfaces, not a text color - against the `#0a0a0c` page background
  this rendered as text with almost no contrast, confirmed
  near-invisible in the live screenshot. Replaced all three with the
  pattern already used at all ~12 other `<Link>` call sites across the
  app (plain `text-foreground`, `underline` on hover/always) - this
  makes the fix a consistency fix, not an invented new pattern.
- **Stale comment, 1 site**: `Findings.tsx`'s file-header comment still
  described the pre-17.11 400 boundary for Integrity-Review-backed
  workspaces ("this screen shows a plain explanatory message... does
  not attempt to extend that backend boundary") - incorrect since
  17.11 fixed exactly that boundary. Rewritten to describe the current,
  correct behavior.

## Exclusions
- **Did not touch severity badge colors** (`Findings.tsx`'s
  critical/high/medium/low/informational badge palette, including
  `low` using a blue tone). Initially flagged as a possible D12
  violation ("one blue accent reserved for links/focus/selection") but
  verified against `static/workspace.css`'s own pre-existing
  `.ws-severity-low` rule (`#0e2636`/`#93c5fd`, also blue) before
  touching anything - the two stacks already agree, and severity-color
  convention (red/orange/yellow/blue-ish) is a distinct, standard
  semantic scale orthogonal to D12's brand-accent rule. Changing it
  would have been an uninformed "fix" to something that was already
  correct.
- **Did not add a "New mandate" CTA to `MandatesHome.tsx`** despite its
  visible asymmetry with `Deals.tsx`'s header `+ New deal` button.
  `MandatesHome.tsx`'s own comment documents this as a deliberate
  decision (`MandateList.tsx` stays the deal-scoped creation surface,
  since creating a mandate requires a deal context this cross-deal
  register doesn't have) - an information-architecture decision, not a
  design-system consistency defect, and out of this task's scope to
  reverse unilaterally.
- **No animation/motion work** - per CLAUDE.md's precedence rule and
  the product's own stated identity (clarity and professional
  credibility over consumer-style flourish), and because no missing- or
  broken-feedback issue was actually found in the live audit that would
  have justified it (existing `transition-all duration-200
  hover:-translate-y-0.5` on engagement cards was left as-is - subtle,
  purposeful, not excessive).
- **No change to `frontend/src/index.css`'s token values themselves** -
  the Meridian retheme (D12/D13) was already correctly applied before
  this task started; the defects found were call-site token misuse, not
  a broken palette.
- **No change to shadcn/ui primitives** (`components/ui/*`) - vendored,
  generated code; a `<button>`-without-inline-`className` grep hit
  there was a false positive (styling applied via `cn(...)` a few lines
  below the opening tag).
